# 삼국통일 FreeNet 런처

시험 버전: **1.10.0 (관전자 슬롯, 기본 꺼짐)**

관전 기능의 실제 3대 PC 검증은 아직 하지 않았습니다. 이번 시험 패키지는 GitHub 시험 릴리스(`v1.10.0-test.1`)로 제공하며 자동 업데이트 대상에는 포함하지 않습니다. 기존 공개 업데이트 정보는 변경하지 않았습니다.

## 관전자 슬롯 시험 방법

1. 세 PC에 같은 1.10.0 패키지를 풀고 `SamKookLauncher.exe`를 실행합니다. 각 PC의 원본 게임 경로를 지정합니다.
2. 플레이어 2대와 관전자 1대 **모두** `관전자 슬롯 (시험 / 모든 PC 동일 설정)`을 켭니다. 저지연·36명·쌀 집결 설정도 서로 맞춥니다.
3. 방장은 플레이어로 남습니다. 세 명이 방에 입장한 뒤, 방장이 세 번째 참가자의 슬롯 메뉴에서 `관전자`를 선택합니다. 해당 슬롯에 `관전자 이름`이 표시되는지 모든 PC에서 확인하고 시작합니다. 빈 슬롯을 미리 관전자로 지정하는 방식도 지원합니다.
4. 플레이어 둘은 기존대로 대전합니다. 관전자는 기존 시야공유 처리를 통해 양쪽 시야를 받습니다. 관전자 슬롯의 시작 건물·유닛·자원 생성과 게임 명령을 차단하고, 승패 판정에서 제외합니다. 플레이어끼리 시야를 자동 공유하거나 동맹을 맺지는 않습니다.
5. 복귀하려면 모든 PC에서 게임을 종료하고 관전 옵션을 끈 뒤 다시 실행하세요. 원본 `SamKook.exe`는 수정하지 않습니다.

### 시험 범위와 제한

- 일반 대전맵의 **새 게임**으로 시험하세요. 관전자는 기존 슬롯 한 칸을 사용하며, 방장은 관전자가 될 수 없습니다. 저장 게임·시나리오·방장 교체는 지원하지 않습니다.
- 관전 모드와 일반 모드는 별도 DirectPlay 애플리케이션 GUID를 사용합니다. 구버전/옵션을 끈 PC는 관전 모드 대전에 입장할 수 없습니다. 로비 방 목록에 보이더라도 옵션을 맞추기 전에는 참가하지 마세요.
- 관전자는 카메라 이동과 관찰·일반 채팅을 할 수 있도록 기존 입력을 유지하고, 이동·생산·외교·속도 변경 등 게임 명령은 송신과 수신 양쪽에서 차단합니다.
- 관전자도 기존 lockstep 통신에 참여합니다. 관전자 네트워크 단절 시 원래 게임의 대기/퇴장 절차가 적용되므로, 지연 없이 즉시 분리되는 별도 스트리밍 관전 방식은 아닙니다.
- 관전자에게 승리/패배 화면을 띄우지 않습니다. 대전 종료 후에는 직접 나가세요. 실제 퇴장 후 플레이어의 대전 지속 여부는 아래 항목으로 확인해야 합니다.
- 자동 테스트: 역할 패킷 직렬화/검증, 송신 큐 원문 보존, 슬롯 UI 인덱스/이름 유지, 448개 시야 조합(12/36명 각각), 명령 송수신 차단, 초기 생성 제외, 승패 제외, 퇴장 시 다른 플레이어 상태 보존, 싱글플레이 분리 및 기존 편의 기능 회귀 검증을 통과했습니다. 이는 실제 렌더링·DirectPlay 연결의 완료 검증이 아닙니다.

### 3대 PC에서 확인할 항목

- 세 PC 모두 같은 슬롯을 관전자로 표시하고 게임을 시작하는가?
- 관전자는 양쪽 지형·유닛·미니맵 시야를 보며, 플레이어끼리는 상대 시야가 보이지 않는가?
- 관전자에게 시작 유닛·본영이 없고, 다른 유닛의 이동·생산 명령을 내릴 수 없는가?
- 플레이어의 이동·생산·전투가 서로 일치하며 동맹 화면을 변경해도 관전 시야가 유지되는가?
- 관전자가 먼저 나간 뒤 플레이어 둘이 계속 이동·생산·전투할 수 있는가?
- 한 플레이어가 패배했을 때 다른 플레이어에게 정상적으로 승리가 적용되는가?

문제가 있으면 어떤 단계인지와 세 PC의 `freenet.log`를 보내주세요. 로그는 실행한 런처와 같은 폴더에 생성됩니다. 충돌 진단 모드를 켠 경우 `runtime/original/crashes` 또는 `runtime/display/crashes`에도 진단 자료가 생성됩니다. 로그에는 선택한 관전 모드와 프로토콜 버전이 기록됩니다.

## 본영 쌀 집결 자동 채집

- `쌀 집결 자동 채집`은 기본 활성화입니다. 본영에서 집결 장소(R)를 쌀 지형으로 지정하면 **이후 생산되는 일꾼**이 이동 대신 기존 쌀 채집 명령을 수행합니다. R → 왼쪽 클릭과 우클릭 집결 모두 적용됩니다.
- 세 진영 일꾼을 지원합니다. 일반 땅·쌀이 아닌/고갈된 지형·전투 유닛·집결 미지정은 기존 동작을 유지합니다. 이미 생산된 일꾼의 명령을 바꾸지는 않습니다.
- **멀티플레이 전원이 v1.9.0 이상이고 이 옵션이 동일해야 합니다.** 생산 후 시뮬레이션 명령이 달라지므로 구버전 또는 옵션 혼용은 동기화 오류를 일으킬 수 있습니다. 문제가 있으면 모든 PC에서 끄고 게임을 다시 실행하세요.
- 자동 테스트에서는 실제 x86 생산·채집 명령 코드의 결과를 수동 채집 결과와 비교하고, 독립 수신자 상태·일반 집결 유지·선택 12/36명 호환을 확인했습니다. 실제 화면에서의 채집 및 두 PC 대전 최종 확인은 별도로 필요합니다.

## 서버 없이 싱글플레이 / 서버 시작 안내

- `게임 실행`은 서버 연결 검사·서버 자동 시작 없이 실행합니다. 싱글플레이는 서버가 꺼져 있어도 가능합니다. 접속 IP가 비었거나 잘못되었으면 이번 실행에만 127.0.0.1을 사용하고 안내 로그를 남깁니다.
- 멀티플레이 시 호스트 PC에서만 `로컬 서버 시작`을 누르세요. 시작 전에 “당신이 서버가 맞나요? 상대방에게 당신의 라드민 아이피를 알려주세요.” 확인창을 표시합니다. `예`를 눌러야 시작합니다.
- 버튼을 누르는 시점에 이 PC의 활성 네트워크 어댑터에서 26.x.x.x IPv4 주소를 조회합니다. 여러 개면 모두 표시하며, 없으면 라드민 VPN 연결 확인 안내를 표시합니다. 저장된 상대 서버 IP를 자신의 IP로 오인해 표시하지 않습니다.
- 상대 PC는 안내받은 IP를 `접속 서버 IP`에 입력하세요. 필요하면 `서버 연결 테스트` 버튼으로 연결을 별도로 확인할 수 있습니다. 서버 중지는 확인창 없이 동작합니다.

## 우클릭 집결 장소·인게임 타이머

- `우클릭 집결 장소 지정`, `우측 상단 게임 타이머`는 기본으로 켜집니다. 게임 종료 후 런처 업데이트 → 게임 재실행 시 적용됩니다. 각 옵션을 끄고 재실행하면 원래 동작으로 돌아갑니다.
- 집결 장소(R) 버튼이 활성화된 내 건물을 선택하고 **주 게임 화면의 지형을 우클릭**하면 기존 R → 왼쪽 클릭과 같은 집결 명령이 전송됩니다. R키 방식도 그대로 사용할 수 있습니다.
- 일반 유닛 이동·공격, 적 건물, 미니맵 우클릭, 채팅·메뉴, 명령 지정 중 우클릭 취소 동작은 변경하지 않습니다. 미니맵 우클릭 집결은 이번 기능에 포함하지 않습니다.
- 타이머는 화면 우측 상단에 `시:분:초`로 표시됩니다. 기존 임무 카운트다운 아래쪽에 게임 자체 글자 출력 함수를 사용하므로 외부 오버레이 창이 필요 없습니다.
- 타이머는 기존 임무 타이머와 같은 **게임 진행 시간(30 시뮬레이션 틱 = 1초)**입니다. 현실 시계와 다를 수 있으며 게임 속도의 영향을 받습니다. 기존 저장/불러오기 진행 카운터를 그대로 읽고 게임 동기화 상태는 수정하지 않습니다.
- 두 기능은 기존 명령 형식을 유지합니다. 단, 저지연·36명 선택 옵션에 대한 모든 PC 동일 설정 조건은 계속 적용됩니다.
- 자동 검증: 12명/36명 모드 모두 기존 R키 방식과 동일한 패킷 생성, 독립 수신 클라이언트 코드의 집결 좌표 적용, 14개 입력 보호 조건, 타이머 경계값·레지스터/스택 보존, 기존 선택·송신 패치 회귀 테스트. 실제 게임 화면과 두 PC 대전에서의 최종 확인은 별도로 필요합니다.
- 원본 `SamKook.exe`는 변경하거나 배포하지 않습니다. 런처가 실행용 복사본에만 변경 사항을 적용합니다.

## 유닛 선택 36명

- 게임을 종료하고 런처 업데이트를 적용한 뒤 `유닛 선택 36명`을 체크하고 게임을 실행합니다. 기본값은 원본 12명이며 설정은 보존됩니다.
- **멀티플레이 전원이 v1.7.0 이상에서 같은 선택 설정을 사용해야 합니다.** 구버전·12명 모드와 혼용하지 마세요. 명령 패킷이 달라 동기화 오류가 날 수 있습니다.
- 선택 배열·부대 배열을 별도 영역으로 이동하고, 선택/해제, 부대 저장/호출, 명령 수신·처리, 사망 유닛 정리 루프를 함께 확장했습니다.
- 기존 플레이어 간격 1124바이트 안에 선택 목록과 14개 부대를 유지하는 상한이 36명입니다: `15 × (36+1) × 2 = 1110`. 37명은 1140바이트가 필요합니다. 엔진 전체의 이론적 최대치라는 뜻은 아닙니다.
- 초상화는 기존 12칸을 유지합니다. 첫 12명만 보이지만 선택된 36명 모두 명령 대상입니다. 게임 전체 생산 제한·인구수는 바꾸지 않습니다.
- 기존 저장 파일 형식과의 호환 때문에 **저장 후 불러오면 각 부대는 첫 12개 슬롯까지만 복원됩니다.** 게임 내 유닛 자체는 삭제되지 않습니다. 불러온 뒤 다시 36명으로 선택·지정할 수 있습니다.
- 원본 EXE는 보존하며 실행용 복사본에만 적용합니다. 체크 해제 후 다시 실행하면 기존 12명으로 돌아갑니다.
- x86 에뮬레이션: 36명 선택, 84바이트 명령 송수신/체크섬, 8명 플레이어 × 14개 부대 저장·해제·호출, 명령 적용, 사망 유닛 정리, 저장 호환·새 맵 초기화 테스트 통과. **실제 두 PC 대전 검증은 아직 하지 않았으므로 실험 기능입니다.**

## 맵 미니맵 프리뷰

- 런처의 `맵 미니맵 프리뷰`에서 `Mission` 폴더의 SKM 맵 목록과 지형 구조를 확인할 수 있습니다.
- `P32M` 서명·크기·지형 타일 범위를 검증하며, 손상된 맵은 오류로 표시합니다.
- v1.7.0은 `MapEditor.dll`의 `_drawSmallMap@4` 결과와 해당 계절의 실제 팔레트를 사용합니다. 에디터의 136×136 미니맵이며 고해상도 지형 렌더링은 아닙니다.
- DLL 해시를 확인하고 별도 32비트 프로세스에서 렌더링합니다. 로딩은 비동기로 처리하고 제한 시간을 둡니다. 에디터 DLL·게임 리소스는 배포에 포함하지 않고 사용자의 게임 폴더에서 읽습니다.

## 이전 선택 제한 검토

`SamKook.exe`의 선택 제한은 하나의 숫자만 바꾸는 구조로 확인되지 않았습니다. 선택 목록, UI 슬롯, 명령 패킷의 고정 크기가 연결되어 있어 일부 비교값만 늘리면 메모리 손상·명령 누락·멀티 동기화 오류가 발생할 수 있습니다. v1.6.0에서는 안전하게 검증할 수 없어 선택 수를 변경하지 않았습니다.

- `멀티 저지연`은 원본의 명령 버퍼 기준 0/2/4/6을 0/0/1/2로 줄이고, 멀티 동기화 검사 주기를 6프레임에서 3프레임으로 줄입니다.

- `송신 스레드 CPU 점유 완화`는 반복문에서 고정 1ms 대기 대신 나머지 타임 슬라이스만 양보하도록 변경했습니다.
- 원본 `SamKook.exe`는 변경하지 않고 `runtime`의 실행용 복사본에만 패치합니다.

- Alt+Enter는 창모드와 테두리 없는 전체화면 사이를 전환합니다.

- 게임을 종료한 뒤 런처 업데이트를 적용하고 다시 실행해야 새 설정이 생성됩니다. 원래 전체화면 모드는 변경하지 않습니다.

## 네트워크 입력 지연 조사와 적용 범위

게임의 실제 대전 명령은 DirectPlay Send/Receive 경로(0x43974A/0x439CDF 등)를 사용합니다.
로비 TCP 서버는 방 검색과 채팅용이므로 이것만 최적화해서 대전 명령 지연을 해결할 수는 없습니다.
0x439EB9의 2000ms는 누락된 동기화 응답을 기다리는 중의 처리 기준이고,
게임 턴 간격에는 30~50ms 조절 코드가 있습니다. 이것들을 근거 없이 줄이거나 제거하지 않았습니다.

- `송신 스레드 CPU 점유 완화`: 0x44A1A0의 무대기 반복마다 Sleep(0)으로 타임 슬라이스를 양보합니다. 레지스터·플래그·스택 보존 및 기존 큐 패치를 에뮬레이션으로 검증했습니다. 문제가 생기면 체크를 해제하고 다시 실행하세요.
- 일반 실행은 디버거를 붙이지 않습니다. 충돌 조사 때만 `충돌 진단 모드`를 켜세요.
- 화면 모듈은 VSync를 끄고 단일 CPU 강제 고정을 사용하지 않으며 자체 게임 틱 제한을 끕니다. 출력은 60fps로 제한하지만 게임 시뮬레이션 속도는 변경하지 않습니다.
- `네트워크 지연 측정`은 입력된 서버 IP까지 ICMP 5회 최소/평균/최대 및 응답 수를 기록합니다. 실제 DirectPlay 왕복 시간과 같지 않으며 ICMP 차단을 패킷 손실로 단정할 수 없습니다.

**약 1초 명령 지연의 원인 및 개선 폭은 아직 실측으로 확정하지 못했습니다.**
B PC에서 26.157.67.215까지 측정하고, 양쪽 모두 같은 버전으로 같은 LAN/VPN 환경에서 비교하세요.
한 PC 자신에게 ping한 결과는 원격 지연 진단에 도움이 되지 않습니다. VPN 경로/손실/느린 참가자도 확인해야 합니다.

화면 모듈, 라이선스, 실행 파일, 업데이트 도우미는 모두 업데이트 ZIP에 포함됩니다.
화면·성능 설정 파일과 계정 DB는 업데이트 시 덮어쓰지 않습니다. `package.ps1`이 배포 파일 목록과 모듈 해시를 확인합니다.
업데이트의 새 모듈 포함, 필수 파일 누락 거부, 정상 재시작과 실패 복구를 테스트합니다.
cnc-ddraw 출처 및 설정: https://github.com/FunkyFr3sh/cnc-ddraw/tree/v7.1.0.0 (세부 해시는 vendor/cnc-ddraw/PROVENANCE.md).

## 사용법

1. `SamKookLauncher.exe`를 실행합니다.
2. 게임 경로가 다르면 `찾기`에서 `SamKook.exe`를 선택합니다.
3. `게임 실행`을 누릅니다.
4. 게임에서 `함께하기 → 인터넷 플레이`로 들어갑니다.

### 두 PC 연결

- A PC: `접속 서버 IP`를 `127.0.0.1`로 두고 `로컬 서버 시작`을 누릅니다.
- B PC: `접속 서버 IP`에 A PC의 LAN, Radmin VPN 또는 Hamachi IPv4 주소를 입력하고 게임을 실행합니다.
- A PC의 방화벽과 공유기에서 TCP 7104 접근이 가능해야 합니다.
- `hosts 파일 열기` 버튼은 Windows hosts 파일을 메모장으로 엽니다. 저장에 관리자 권한이 필요할 수 있습니다.

현재 서버는 계정 인증, 채널 입장, 방 생성·조회 및 로비 채팅을 제공하는 초기 호환 서버입니다. 사용자 목록과 비밀번호 방 참여는 미구현이며 실제 방 참여·대전은 검증되지 않았습니다. 인터넷 공개 운영은 권장하지 않습니다.

접속 및 패킷 기록은 런처 폴더의 `freenet.log`에도 저장됩니다. 오류가 생기면 이 파일을 확인합니다.

계정 생성과 로그인을 지원합니다. 계정 정보는 `accounts.db`에 저장되며 게임이 생성한 비밀번호 검증값만 기록하고 입력한 비밀번호 평문은 저장하지 않습니다.
동일한 계정 생성 요청이 재전송되면 같은 비밀번호일 때 성공으로 처리하고, 다른 비밀번호일 때만 중복 계정으로 거부합니다.

## 런처 업데이트 배포

`런처 업데이트` 버튼은 TLS 1.2로 GitHub Releases를 먼저 확인하고, Release가 없으면 저장소의 `update.json`을 확인합니다. 새 버전 ZIP을 내려받아 런처 종료 후 교체하고 자동으로 다시 실행합니다.

## 빌드

PowerShell에서 `build.ps1`을 실행합니다. Windows에 포함된 .NET Framework C# 컴파일러를 사용하므로 별도 SDK가 필요 없습니다.
