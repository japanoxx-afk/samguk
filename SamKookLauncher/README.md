# 삼국통일 FreeNet 런처

배포 버전: **1.12.1 (상태 지문 정밀화 및 로비 복귀 원인 즉시 안내)**

기존 런처의 `런처 업데이트` 버튼으로 v1.12.1을 받을 수 있습니다. 관전 기능은 계속 시험 기능이며 기본 꺼짐입니다.

## v1.12.1: 상태 지문 정밀화

- v1.12.0이 프레임 12027에서 실제로 서로 다른 지문을 감지한 사례를 반영했습니다.
- 지문을 RNG, 플레이어 상태·자원, 유닛·건물 핵심 상태, 생산 대기열로 분리해 다음 기록에서 최초로 달라진 영역을 알 수 있습니다.
- 의미가 확정되지 않은 유닛 필드는 비교 대상에서 제외해 PC별 화면·UI 상태가 오탐을 만들 가능성을 줄였습니다.
- 게임 프로세스가 종료되지 않고 로비로 돌아온 경우에도 런처가 진단 파일을 즉시 감지해 원인을 안내합니다.
- 모든 참가 PC가 v1.12.1이어야 합니다.

## v1.12.0: 조용한 동기화 분리 감지

- 매 동기화 장벽에서 RNG, 플레이어 자원, 유닛·건물의 핵심 상태를 지문으로 만들어 참가 PC끼리 비교합니다.
- 지문이 다르면 각자 다른 게임을 계속 진행하지 않고 대전을 중단하며 `sync-logs`에 양쪽 지문과 상대 슬롯을 기록합니다.
- 기존 상대 제외·검사값·잘못된 유닛 행동 차단도 유지합니다.
- 자동 재동기화 기능은 아닙니다. 불일치 상태를 한쪽 데이터로 덮어쓰면 오히려 손상이 커질 수 있어 안전 중단과 최초 지점 기록을 우선합니다.
- 모든 참가 PC가 v1.12.0이어야 합니다. 새 동기화 프로필로 구버전과의 혼합 접속을 차단합니다.

## v1.11.2: 대전 중 행동 처리 충돌 수정

- 9월 21일 01:55:26 충돌 덤프에서 병사 ID 100에 건물 전용 상태 `0x1081`이 기록되어, 행동 함수 표 밖의 문자열을 함수 주소 `0x4403691E`로 호출한 것을 확인했습니다. 건물 업그레이드 요청을 병사에게 적용했을 때 원본의 동일한 충돌 경로를 재현했습니다. 그 요청이 실제 대전에서 만들어진 최초 경위까지 확인된 것은 아닙니다.
- 해당 멀티 요청은 살아 있는 건물에만 적용하며 대상 ID·소유자·대기열 인덱스·건물 종류를 검증합니다. 잘못된 대상은 자원 차감과 상태 변경 전에 거부합니다. AI의 같은 건물 전용 처리에도 대상 종류 검사를 추가했습니다.
- 유닛 행동 함수 표의 64개 항목 범위를 벗어나면 잘못된 주소를 호출하지 않고 게임 안전성 보호로 종료 요청을 남깁니다. 임의로 유닛을 삭제하거나 정상 상태로 덮어쓰지 않습니다. `sync-logs`에 유닛 ID·행동 코드·종류를 추가 기록합니다.
- **모든 PC를 v1.11.2로 업데이트하고 기존 네 가지 멀티 옵션을 맞추세요.** 이전 버전과의 대전 연결을 분리합니다. 원본 게임은 보존합니다.
- 원본 충돌 재현, 잘못된 대상/인덱스 거부, 정상 건물 업그레이드의 원본과 동일한 처리, 행동 인덱스 256개 및 기존 기능 자동 테스트를 수행했습니다. 실제 장시간 멀티 검증은 필요하며 모든 충돌이나 동기화 문제를 해결했다는 뜻은 아닙니다.

## v1.11.1: 분리 진행 보호 및 동기화 진단

- 원본에는 응답 대기 후 상대 제외, 원본 검사값 불일치, 상대의 강제 제외 통지 처리에서 상대를 삭제하고 대전을 계속하는 경로가 있습니다. 원본 A/B가 서로를 제외하고 각각 게임을 계속하는 경로를 x86 테스트로 재현했습니다(사람 2명+컴퓨터 구성, 네트워크 API는 모의 처리).
- 해당 경로에서 다른 플레이어의 유닛·소유권을 변경하기 전에 대전을 중단하도록 했습니다. **통신 장애나 최초 상태 불일치를 고친 패치도, 자동 재동기화 기능도 아닙니다.** 정상적인 자진 퇴장 경로는 그대로 유지합니다. 응답 없는 상대를 제외하고 계속하기는 이제 대전 중단으로 처리합니다.
- 보호 작동 시 런처의 `sync-logs` 폴더에 실행별 `.bin` 진단을 남깁니다. 게임 프로그램을 종료하면 `.txt`와 런처 경고가 생성됩니다. 프레임·난수/호출 수·원본 검사값·플레이어 상태·통신 큐 인덱스만 기록하며 계정·비밀번호·채팅·메모리 덤프는 포함하지 않습니다. 최초 불일치 이전의 명령 이력은 기록하지 않습니다.
- **모든 PC를 v1.11.1로 업데이트하고 저지연·36명 선택·쌀 집결·관전 옵션을 동일하게 맞추세요.** 이 네 설정이 다른 PC는 DirectPlay 대전 연결을 분리합니다. 로비 목록에 방이 보이더라도 설정이 다르면 입장할 수 없습니다. 화면 비율·타이머·우클릭 집결·서버 IP는 이 호환성 구분에 포함하지 않습니다.
- 원본 검사/제외 경로에 도달하지 않는 상태 불일치는 아직 감지하지 못합니다. 동일한 문제가 생기면 A/B의 `freenet.log`, `sync-logs` 기록(있는 경우), 맵 이름과 처음 달라진 게임 시각·행동이 필요합니다. 파일은 자동 업로드하지 않습니다.
- 보호 경로·로그 쓰기 실패·기존 대기 루프 종료·일반/싱글플레이 경로 및 기존 기능 테스트를 통과했습니다. 실제 여러 PC 대전의 장시간 동기화는 미검증입니다.

## v1.11.0: 방장 관전 및 읽기 전용 정보 조회

- 방장도 자기 슬롯에서 `관전자`를 선택할 수 있습니다. 네트워크 방장 역할은 유지하며 게임 명령·초기 유닛 생성·개인 패배 판정에서는 제외합니다. 대전 중 방장의 접속을 유지하세요.
- 관전자를 제외한 사람+컴퓨터가 합계 2명 이상이면 시작할 수 있습니다. 방장 관전자+사람 플레이어+컴퓨터, 방장 관전자+컴퓨터 2명 구성을 지원합니다. 맵에 관전자 포함 슬롯 수가 충분해야 합니다.
- 관전자가 살아 있는 플레이어의 유닛·건물을 클릭하면 기존 상단 자원/인구 표시가 해당 소유자 기준으로 바뀝니다. `OBS P번호`는 방 슬롯 번호입니다. 선택이 없거나 대상이 부적합하면 기본 표시로 돌아갑니다.
- 선택한 건물의 유닛 생산 대기열은 `Q번호: 유닛 이름 x수량 (진행률%)`로 표시합니다. 육상·해상 유닛 생산을 지원하며 해당 대기열이 없으면 `Production: -`를 표시합니다. 기존 건물 상세 표시의 소유자 제한도 관전자에게만 해제합니다.
- 정보 조회는 화면 표시만 변경합니다. 실제 플레이어 ID, 자원, 유닛 소유권을 바꾸지 않으며 관전자의 이동·생산 명령은 계속 차단합니다.
- **모든 PC를 v1.11.0으로 업데이트하고 관전 옵션을 동일하게 켜세요.** 방장 관전을 지원하는 관전 프로토콜 2로 변경하여 v1.10.x와 대전 연결을 분리했습니다.
- x86 에뮬레이션으로 방장/일반 관전자, 생산 정보·진행률·자원 소유자 표시, 명령 차단, 승패 판정과 기존 기능 회귀를 검증했습니다. 실제 화면 배치 및 여러 PC 동기화는 업데이트 후 확인이 필요합니다.

## v1.10.3: 관전 시작 직후 패배 알림 수정

- 일반 승패 콜백 뒤에 별도로 실행되는 `내 유닛과 건물이 모두 없으면 패배` 검사가 관전자를 탈락시키던 문제를 수정했습니다. 관전자는 원래 유닛·건물을 생성하지 않으므로 이 마지막 검사에서만 제외합니다.
- 플레이어·컴퓨터의 전멸 처리와 정상 승리/패배 판정, 양쪽 시야 공유는 유지합니다. 강제로 동맹을 맺거나 가짜 유닛을 생성하지 않습니다.
- v1.10.2 실행본의 전체 승패 처리 경로에서 관전자 패배창을 재현했고, 수정본의 12명/36명 모드에서 모든 비방장 관전 슬롯 및 100회 반복 판정, 플레이어 패배·컴퓨터 전멸 후 승리 유지 테스트를 통과했습니다.
- A 서버·A 관전자 / B 방장 플레이어 / 컴퓨터 구성의 실제 두 PC 재검증은 필요합니다. 양쪽 모두 업데이트한 뒤 게임을 새로 실행하세요.

## v1.10.2: 연결 정리 안정화 및 재검증 필요

- 해제한 DirectPlay 로비 객체의 포인터를 즉시 비워 반복 정리 시 중복 해제를 방지합니다.
- 성공한 COM 초기화(S_OK/S_FALSE)에 대해서만 종료를 호출합니다. 초기화 실패 또는 중복 정리 시 다른 구성 요소의 COM 참조를 잘못 줄이지 않습니다.
- 원본 x86 코드에서 두 결함을 재현했고 수정본의 초기화 실패·반복 정리·100회 재입장 수명 테스트를 통과했습니다. 네트워크를 실제로 연결한 100회 테스트는 아닙니다.
- **보고된 A 서버 → B 방 입장 충돌이 해결됐다는 뜻은 아닙니다.** 기존 덤프만으로 최초 메모리 손상 원인은 확정되지 않았습니다. 두 PC 모두 업데이트 후 관전 옵션을 켜고 같은 구성으로 재확인해야 합니다. 관전 옵션을 끈 상태의 입장 성공은 사용자 확인을 받았습니다.
- 원본 게임은 보존하며 새 런처로 실행할 때 패치된 실행본을 재생성합니다. 관전 프로토콜과 서버/방장 IP는 변경하지 않습니다.

## v1.10.1: 두 PC로 관전 시험

- v1.10.0에서 관전자를 제외한 뒤에도 기존 `사람 2명 이상 또는 컴퓨터 3명 이상` 조건이 남아 있었습니다. 이를 **사람 플레이어가 최소 1명이고, 사람+컴퓨터 합계가 2명 이상**인 조건으로 수정했습니다. 관전자는 대전 인원수에 포함하지 않습니다.
- 두 PC 모두 업데이트하고 관전 옵션을 켠 뒤, **A(방장)=플레이어 / B=관전자 / C 슬롯=컴퓨터**로 새 게임을 시작할 수 있도록 했습니다. 관전자도 슬롯을 사용하므로 최소 3슬롯을 지원하는 맵(예: N4 맵)을 선택하세요.
- A 플레이어+B 관전자만 있고 컴퓨터가 없는 구성은 대전 상대가 없어 시작하지 않습니다.
- **방장은 여전히 관전자로 바꿀 수 없습니다.** 이번 수정은 사람+컴퓨터 혼합 구성의 시작 차단 문제를 해결하며, 방장 관전 기능을 추가하지 않습니다.
- 실제 x86 시작 인원 집계 루프부터 승인/거부 분기까지 165개 구성을 12명/36명 모드 각각 검증했습니다. 사용자가 보고한 두 PC의 실제 시작·시야·퇴장 동작은 업데이트 후 확인이 필요합니다.

## 관전자 슬롯 시험 방법

1. 참가 PC 모두 게임을 종료하고 기존 런처의 `런처 업데이트`를 누릅니다. 재시작 후 v1.12.1 표시를 확인합니다. 처음 설치하는 PC만 ZIP을 풀고 원본 게임 경로를 지정합니다.
2. 플레이어와 관전자 PC **모두** `관전자 슬롯 (시험 / 모든 PC 동일 설정)`을 켭니다. 저지연·36명·쌀 집결 설정도 서로 맞춥니다. 두 PC 시험은 위의 컴퓨터 포함 구성을 사용하세요.
3. 방장이 자신 또는 다른 참가자의 슬롯 메뉴에서 `관전자`를 선택합니다. 해당 슬롯에 `관전자 이름`이 표시되는지 모든 PC에서 확인하고 시작합니다. 빈 슬롯을 미리 관전자로 지정하는 방식도 지원합니다. 관전자 외 사람·컴퓨터가 합계 2명 이상 필요합니다.
4. 플레이어 둘은 기존대로 대전합니다. 관전자는 기존 시야공유 처리를 통해 양쪽 시야를 받습니다. 관전자 슬롯의 시작 건물·유닛·자원 생성과 게임 명령을 차단하고, 승패 판정에서 제외합니다. 플레이어끼리 시야를 자동 공유하거나 동맹을 맺지는 않습니다.
5. 복귀하려면 모든 PC에서 게임을 종료하고 관전 옵션을 끈 뒤 다시 실행하세요. 원본 `SamKook.exe`는 수정하지 않습니다.

### 시험 범위와 제한

- 일반 대전맵의 **새 게임**으로 시험하세요. 관전자는 기존 슬롯 한 칸을 사용하며 방장도 관전할 수 있습니다. 저장 게임·시나리오·방장 교체는 지원하지 않습니다. 방장 퇴장 후 대전 지속은 지원하지 않습니다.
- 관전 모드와 일반 모드는 별도 DirectPlay 애플리케이션 GUID를 사용합니다. 구버전/옵션을 끈 PC는 관전 모드 대전에 입장할 수 없습니다. 로비 방 목록에 보이더라도 옵션을 맞추기 전에는 참가하지 마세요.
- 관전자는 카메라 이동과 관찰·일반 채팅을 할 수 있도록 기존 입력을 유지하고, 이동·생산·외교·속도 변경 등 게임 명령은 송신과 수신 양쪽에서 차단합니다.

## 유닛 선택 36명

- 게임을 종료하고 런처 업데이트를 적용한 뒤 `유닛 선택 36명`을 체크하고 게임을 실행합니다. 기본값은 원본 12명이며 설정은 보존됩니다.
- **멀티플레이 전원이 v1.7.0 이상에서 같은 선택 설정을 사용해야 합니다.** 구버전·12명 모드와 혼용하지 마세요. 명령 패킷이 달라 동기화 오류가 날 수 있습니다.
- 선택 배열·부대 배열을 별도 영역으로 이동하고, 선택/해제, 부대 저장/호출, 명령 수신·처리, 사망 유닛 정리 루프를 함께 확장했습니다.
- 기존 플레이어 간격 1124바이트 안에 선택 목록과 14개 부대를 유지하는 상한이 36명입니다: `15 × (36+1) × 2 = 1110`. 37명은 1140바이트가 필요합니다. 엔진 전체의 이론적 최대치라는 뜻은 아닙니다.
- 초상화는 기존 12칸을 유지합니다. 첫 12명만 보이지만 선택된 36명 모두 명령 대상입니다. 게임 전체 생산 제한·인구수는 바꾸지 않습니다.
- 기존 저장 파일 형식과의 호환 때문에 **저장 후 불러오면 각 부대는 첫 12개 슬롯까지만 복원됩니다.** 게임 내 유닛 자체는 삭제되지 않습니다. 불러온 뒤 다시 36명으로 선택·지정할 수 있습니다.
- 원본 EXE는 보존하며 실행용 복사본에만 적용합니다. 체크 해제 후 다시 실행하면 기존 12명으로 돌아갑니다.
- x86 에뮬레이션: 36명 선택, 84바이트 명령 송수신/체크섬, 8명 플레이어 × 14개 부대 저장·해제·호출, 명령 적용, 사망 유닛 정리, 저장 호환·새 맵 초기화 테스트 통과. **실제 두 PC 대전 검증은 아직 하지 않았으므로 실험 기능입니다.**

## 이전 선택 제한 검토

`SamKook.exe`의 선택 제한은 하나의 숫자만 바꾸는 구조로 확인되지 않았습니다. 선택 목록, UI 슬롯, 명령 패킷의 고정 크기가 연결되어 있어 일부 비교값만 늘리면 메모리 손상·명령 누락·멀티 동기화 오류가 발생할 수 있습니다. v1.6.0에서는 안전하게 검증할 수 없어 선택 수를 변경하지 않았습니다.

- 원본 `SamKook.exe`는 변경하지 않고 `runtime`의 실행용 복사본에만 패치합니다.

- 창모드와 테두리 없는 전체화면은 GDI 호환 렌더러, 전체 다시 그리기 및 자식 창 다시 그리기를 사용합니다. 로그인 화면 깨짐 완화를 위한 설정이며 실제 게임 화면에서 해결 여부는 아직 확인하지 못했습니다. GDI는 GPU 렌더링보다 CPU 사용량이 늘 수 있습니다.
- 게임을 종료한 뒤 런처 업데이트를 적용하고 다시 실행해야 새 설정이 생성됩니다. 원래 전체화면 모드는 변경하지 않습니다.

## 화면 및 실행 옵션

- `창모드` 또는 `테두리 없는 전체화면` 선택 후 게임을 다시 실행하세요. 원래 전체화면으로 되돌릴 수도 있습니다.
- `16:9 늘려 표시`는 기존 4:3 화면을 가로로 늘리는 기능입니다. 지도 시야 확장이나 엔진 해상도 변경이 아닙니다. 체크 해제 시 4:3을 유지합니다.
- 창 크기는 모니터 작업 영역에 맞춰 최대 높이 720으로 제한합니다. Alt+Enter로 모드를 전환할 수 있습니다.
- cnc-ddraw 7.1.0.0(MIT)을 포함하며 실행용 복사본 옆에만 설치합니다. 원본 게임 EXE와 DLL은 변경하지 않습니다.
- 신규 화면 설정은 호환 모듈 설정 생성·해시 검증까지 테스트했습니다. 실제 게임 화면, 마우스 위치, 맵 선택창은 사용자 PC에서 확인이 필요합니다.

## 네트워크 입력 지연 조사와 적용 범위

게임의 실제 대전 명령은 DirectPlay Send/Receive 경로(0x43974A/0x439CDF 등)를 사용합니다.
로비 TCP 서버는 방 검색과 채팅용이므로 이것만 최적화해서 대전 명령 지연을 해결할 수는 없습니다.
0x439EB9의 2000ms는 누락된 동기화 응답을 기다리는 중의 처리 기준이고,
게임 턴 간격에는 30~50ms 조절 코드가 있습니다. 이것들을 근거 없이 줄이거나 제거하지 않았습니다.

- `송신 스레드 CPU 점유 완화`: 0x44A1A0의 무대기 반복마다 Sleep(0)으로 타임 슬라이스를 양보합니다. 레지스터·플래그·스택 보존 및 기존 큐 패치를 에뮬레이션으로 검증했습니다. 문제가 생기면 체크를 해제하고 다시 실행하세요.
- 일반 실행은 디버거를 붙이지 않습니다. 충돌 조사 때만 `충돌 진단 모드`를 켜세요.
- 화면 모듈은 VSync를 끄고 단일 CPU 강제 고정을 사용하지 않으며 자체 게임 틱 제한을 끕니다. 출력은 60fps로 제한하지만 게임 시뮬레이션 속도는 변경하지 않습니다.
- `네트워크 지연 측정`은 입력된 서버 IP까지 ICMP 5회 최소/평균/최대 및 응답 수를 기록합니다. 실제 DirectPlay 왕복 시간과 같지 않으며 ICMP 차단을 패킷 손실로 단정할 수 없습니다.

**약 1초 명령 지연의 원인 및 개선 폭은 아직 실측으로 확정하지 못했습니다.**
B PC에서 26.157.67.215까지 측정하고, 양쪽 모두 같은 버전으로 같은 LAN/VPN 환경에서 비교하세요.
한 PC 자신에게 ping한 결과는 원격 지연 진단에 도움이 되지 않습니다. VPN 경로/손실/느린 참가자도 확인해야 합니다.

화면 모듈, 라이선스, 실행 파일, 업데이트 도우미는 모두 업데이트 ZIP에 포함됩니다.
화면·성능 설정 파일과 계정 DB는 업데이트 시 덮어쓰지 않습니다. `package.ps1`이 배포 파일 목록과 모듈 해시를 확인합니다.
업데이트의 새 모듈 포함, 필수 파일 누락 거부, 정상 재시작과 실패 복구를 테스트합니다.
cnc-ddraw 출처 및 설정: https://github.com/FunkyFr3sh/cnc-ddraw/tree/v7.1.0.0 (세부 해시는 vendor/cnc-ddraw/PROVENANCE.md).

## 사용법

1. `SamKookLauncher.exe`를 실행합니다.
2. 게임 경로가 다르면 `찾기`에서 `SamKook.exe`를 선택합니다.
3. `게임 실행`을 누릅니다.
4. 게임에서 `함께하기 → 인터넷 플레이`로 들어갑니다.

### 두 PC 연결

- A PC: `접속 서버 IP`를 `127.0.0.1`로 두고 `로컬 서버 시작`을 누릅니다.
- B PC: `접속 서버 IP`에 A PC의 LAN, Radmin VPN 또는 Hamachi IPv4 주소를 입력하고 게임을 실행합니다.
- A PC의 방화벽과 공유기에서 TCP 7104 접근이 가능해야 합니다.
- `hosts 파일 열기` 버튼은 Windows hosts 파일을 메모장으로 엽니다. 저장에 관리자 권한이 필요할 수 있습니다.

현재 서버는 계정 인증, 채널 입장, 방 생성·조회 및 로비 채팅을 제공하는 초기 호환 서버입니다. 사용자 목록과 비밀번호 방 참여는 미구현이며 실제 방 참여·대전은 검증되지 않았습니다. 인터넷 공개 운영은 권장하지 않습니다.
